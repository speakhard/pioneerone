# pioneerone.tv

The site for *Pioneer One* — a six-episode independent science-fiction series
released free online beginning in 2010.

It has one job: someone hears about the show, opens the address on their phone,
and finds something worth their attention. So the homepage leads with the show,
makes the whole season watchable in two taps, and only then explains how it was
made and what is happening now.

## Shape

Static HTML, generated by a Python script. No database, no CMS, no client-side
framework, and no JavaScript at all until a visitor presses play.

    content/*.toml     the writing and the episode data
    templates/         Jinja2 — base, index, story, archive
    static/            CSS, one small script, self-hosted fonts, derived images
    assets-src/        the recovered originals, with provenance in SOURCES.md
    builder.py         content + templates -> site/
    prepare_assets.py  assets-src/ -> static/img/  (run by hand, output committed)
    shoot.py           renders the built site at four device sizes
    tests/             checks on the built output

`builder.py` reaches nothing over the network and holds no credential, so it
runs identically on a laptop and on Cloudflare Pages.

## Build

    python -m venv .venv && .venv/bin/pip install -r requirements.txt
    .venv/bin/python builder.py        # -> site/
    .venv/bin/python -m http.server 8791 --directory site

## Check

    .venv/bin/pip install -r requirements-dev.txt
    .venv/bin/python -m pytest -q      # 12 checks on the built output
    .venv/bin/python shoot.py          # -> shots/, and fails on layout overflow

`shoot.py` needs the dev server running. It reports horizontal overflow, images
that failed to load, and console errors — the three mobile failures that a
screenshot alone will not show you.

## Changing things

**Copy** lives in the templates, because it is prose and prose belongs where it
is read. **Episode data** lives in `content/episodes.toml`. **Site-wide
settings** live in `content/site.toml`.

**The "stay in touch" section** offers whichever of three things is actually
true, decided by `newsletter_mode()` in `builder.py`: a form if
`newsletter.action` names a signup endpoint; a mailto if `fallback_email` is
set *and* `fallback_verified` is true; otherwise the YouTube channel.

An address is never published on the strength of being written down. The domain
has MX records at Bluehost, so mail to an address that does not exist is
accepted and dropped without a bounce — `contact@pioneerone.tv` is exactly that
today. Verify the mailbox by sending it something and watching it arrive, then
set `fallback_verified = true`.

**Adding images** means dropping originals in `assets-src/`, recording where
they came from in `assets-src/SOURCES.md`, and re-running `prepare_assets.py`.
That script never upscales, so a small original stays small rather than being
silently blown up.

## Where the facts come from

Every specific claim on the site — the $6,000, the two million downloads, the
awards, the dates — is sourced in [STORY-SOURCES.md](STORY-SOURCES.md), mostly
to Pioneer One's own writing recovered from the Internet Archive. That file
also records the one date the site corrects, and the handful of things it
deliberately declines to claim.

## Room to grow

The archive is the obvious next thing: 32 production video blogs, scripts,
stills, cut footage, press. Nothing here is in its way — episodes are already
data rather than markup, so per-episode pages, transcripts and richer metadata
are additions rather than a rewrite. The archive page currently says plainly
that it is not open yet, which is better than a thin version of it that is.
